# 13. Propositions and Proofs

PSC1 programs can state logical propositions in the same type system used for
ordinary computation.

## `Prop`

A proposition is a type in `Prop`.

```proofscript
x = x
```

is a proposition.

## Theorems

```proofscript
theorem selfEq {α: Type}(x: α): x = x :=
  by rfl;
```

A theorem declaration contains a proof term or a tactic script that constructs
one.

## Proof terms

Tactics are not trusted oracles.

The path is:

```text
tactic script
-> proof term
-> pskernel
```

pskernel checks the final term.

## Current bounded tactics

The current PSC1 tactic family includes:

```text
exact
exact?
assumption
intro
apply
refine
constructor
cases
induction
rfl
rw
simp only
```

Each is intentionally narrower than the full Lean tactic ecosystem.

## Reflexivity

```proofscript
theorem zeroIsZero: (0: Nat) = 0 :=
  by rfl;
```

`rfl` closes supported equality goals whose sides are definitionally equal.

## Cases

An option law may be proved by checking both constructors:

```proofscript
theorem optionOrElseNoneRight {α: Type}
(value: PsOption(α)):
optionOrElse(value, PsOption.none) = value :=
  by cases value; rfl; rfl;
```

## Induction

Recursive data naturally suggests induction.

The induction principle follows the recursor generated by the inductive type.

## Rewriting

```proofscript
by
  rw [lemma];
```

uses equality evidence to transport the goal.

It is not textual substitution.

## Explicit simplification

PSC1 begins with:

```proofscript
by
  simp only [lemma1(...), lemma2(...)];
```

rather than a large ambient simplifier database.

This keeps early proof behavior predictable and auditable.

## Proof erasure

A proof can influence type checking and then disappear from runtime code.

Its logical role has already been served.
