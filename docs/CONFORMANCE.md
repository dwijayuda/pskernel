
## Lean 4.34 primitive-closure oracle

`npm run oracle:primitive` replays the pinned `oracle/fixtures/lean434-primitive-closure.ndjson` stream through the production importer and kernel. The fixture contains 15,780 export records (12,931 expressions, 348 declaration records) and must result in exactly 390 environment constants. It exercises the real Lean 4.34 dependency closure through `Nat.mod`, `Nat.div`, `Nat.gcd`, and `Nat.bitwise`; no exported primitive declaration is trusted without its production recognizer.

Private Lean names remain structural: `_private.Init.Data.Nat.Bitwise.Basic.0...` contains a numeric `Name.num 0` component and is intentionally not interchangeable with a dotted string component `"0"`.

## Lean 4.34 definitional-equality differential oracle

`npm run oracle:defeq` evaluates the same focused equality/non-equality cases with both the official Lean 4.34.0 toolchain and the TypeScript kernel. The current bounded set passes **24/24** paired cases. Coverage includes beta/zeta/delta behavior, theorem/opaque non-unfolding, function and structure eta, proof irrelevance, projection lazy-delta, Nat and Bool reduction, Nat recursor iota, unit-like equality, Unicode String expansion, quotient lift reduction, and universe `max`/`imax` normalization, plus negative Nat/String/lambda/eta cases.

This is a differential baseline, not an exhaustive equivalence proof; the global differential-oracle gate remains open until substantially broader generated/adversarial coverage exists.

## Adversarial soundness baseline

`npm run oracle:adversarial` runs a bounded set of Lean 4.34's own kernel regression files against the pinned official toolchain:

- `kernelProjIdx.lean` — oversized projection indices must not truncate into valid fields.
- `kernelProjSname.lean` — projection reduction must respect the declared structure family.
- `kernelNestedAuxName.lean` — user declarations may not inject the kernel's reserved `_nested` auxiliaries.
- `kernelMutualDupName.lean` — duplicate names inside a mutual definition block must be rejected transactionally.
- `kernelImaxPropInductive.lean` — `Sort (imax 1 0)` must normalize to `Prop` for inductive-elimination decisions.
- `kernel1.lean` / `kernel2.lean` — large Nat/Bool reduction, `reduceNat`/`reduceBool`, String/Char reduction, and non-reducible partial recursion behavior stay pinned to the official kernel.
- `kernelImaxProp.lean` — normalized-Prop structures remain proof-irrelevant and cannot leak data through projections.
- `kernelMaxRecDepth.lean` — recursion-depth exhaustion is deterministic and succeeds when the explicit budget is raised.
- `kernelErrorFollowup.lean` — rejected declarations containing metavariables do not corrupt subsequent kernel interaction.
- `kernelBacktrack.lean` — kernel errors produced during failed elaboration branches are backtracked rather than poisoning successful alternatives.

The oracle currently passes **13/13** pinned Lean 4.34 kernel regression files. The TypeScript suite contains corresponding direct kernel regressions for the core bug classes, including wrong-family projection reduction, uint32 projection bounds, `_nested` namespace rejection, duplicate mutual-definition names, imax-normalized Prop elimination, and deterministic `maxRecDepth` rejection/success. This gate is still a baseline rather than a claim that Lean's full historical soundness regression corpus has been ported.

### Defeq cache soundness regressions

The adversarial oracle also runs Lean 4.34's `kernel_is_def_eq_equiv_manager_1.lean` and `kernel_is_def_eq_equiv_manager_2.lean`. These regressions protect the 4.34 change away from an equivalence-closure/union-find cache for algorithmic definitional equality. The TypeScript kernel mirrors that design with symmetric positive/negative expression-pair caches only; a unit regression explicitly prevents transitive closure from being introduced into the success cache.

- 1,440 declaration records
- exactly 1,633 admitted/generated constants

The root set covers `Lean.PersistentArrayNode`, `Lean.PersistentArray`, empty/isEmpty, indexed lookup/update, push/pop, conversion, append, list conversion, and statistics. It adds nested recursion through `Array`, proof-carrying bounds, and persistent-array update code to the bounded Lean corpus surface.

This corpus exposed a Lean 4.34 nested-inductive parity bug: the TypeScript implementation reused the inductive header's parameter BinderInfo while transforming/restoring constructor types. Lean recreates the shared parameters from each constructor specifically to preserve constructor-local binder annotations. The TypeScript nested-inductive pipeline now mirrors that behavior during both preprocessing and restoration, while rebasing canonical nested-family parameters to the fresh constructor/restoration locals.

## Native reduction: explicit TCB extension

Lean 4.34 implements `Lean.reduceNat c` / `Lean.reduceBool c` by executing compiler IR for the closed constant `c`. That path observes `[implemented_by]`, `[extern]`, and compiled implementations, so ordinary logical normalization of `c` is not behaviorally equivalent to the official kernel.

The TypeScript checker therefore fails closed on native reduction by default. Full native behavior is exposed through the shape-checked `NativeEvaluator` interface; configuring a provider explicitly extends the trusted computing base, matching Lean's own warning for this deprecated feature. Provider results must match the requested Bool/Nat result kind and Nat results must be non-negative.

The official differential gate now passes **42/42**. Its two native-reduction cases use explicit controlled providers for constants whose official Lean results are known. A standalone TypeScript compiler-IR provider remains an open compatibility gate.
