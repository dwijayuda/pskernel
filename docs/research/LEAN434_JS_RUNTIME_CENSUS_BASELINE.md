## Immediate architectural conclusions

### Parser is not runtime-heavy

The 17 files under `Lean/Parser` contain no quoted extern symbols in this
census. That does **not** mean Parser can compile today: it still depends on
Init, Syntax, Names, parser extension infrastructure, effects, macros and other
language features. But it strongly suggests that once its dependencies exist,
the parser algorithms themselves do not require a large native-runtime shim.

### Init owns most native primitive compatibility

`Init` contributes 591 of the 720 distinct quoted extern symbols found across
the targeted trees. This makes Init/runtime compatibility the correct place to
spend early effort.

The first runtime manifest implements 30 explicit mappings. That number is not
a "4.4% completion" metric: many of the 720 symbols are irrelevant to the
compiler bootstrap, platform-specific, optimization-only, duplicated API
surfaces, or candidates for deferral/replacement. Runtime work should follow a
dependency-closed compiler-source tranche rather than chase raw symbol count.

### Compiler has a meaningful native-facing tail

The Compiler subtree contributes 102 quoted extern symbols. The first JS
bootstrap should therefore continue to use the existing ProofScript checked
core -> erasure -> verified IR -> TypeScript backend, while reusing compiler
support algorithms selectively. Porting all native compiler/codegen facilities
is not a prerequisite for frontend self-hosting.

### Extern and implemented_by need different semantics

An upstream `@[extern "..."] def` may have a logical/reference body that the
kernel checks while execution selects a foreign implementation. It must not be
lowered to ProofScript's existing `extern function` form, because that form is
an explicit logical external assumption/axiom.

The compatible design needs an **execution override sidecar on an ordinary
pskernel-checked declaration**:

```text
Lean source definition
     |
     +---- logical body -----------> pskernel admission
     |
     +---- @[extern "symbol"] -----> JS runtime override metadata
```

Likewise, `@[implemented_by impl]` chooses executable code but does not grant
the implementation proof authority.
