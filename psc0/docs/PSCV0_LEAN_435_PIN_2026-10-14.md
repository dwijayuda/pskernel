## Source study before migration

The complete
[RC4-to-stable comparison](https://github.com/leanprover/lean4/compare/c29b6dda4f7c20e3eeaa717c4e565663c5cfa364...eb6cafb7290e8bd5f2937522d8d804f58f02bafc)
contains two commits and four changed files:

- LeanExport/Json.lean adds strict JSON object parsing with duplicate-key rejection.
- LeanExport/Parse.lean uses complete-input parsing and rejects rebound indices.
- tests/elab/leanExportParse.lean covers trailing input, duplicate keys and rebound indices.
- The upstream CI configuration excludes one flaky async HTTP test under fsanitize.

PSC0's native host uses its own canonical bridge and official addDeclCore;
it does not use LeanExport.Parse. The pinned Init, kernel, elaborator, deriving,
formatting and previously studied tests are byte-unchanged by this comparison.
The migration therefore changes the toolchain and reference identity, not the
selected language semantics. Existing assumptions, signature/status checks,
kernel admission and strict IR acceptance remain required.

## Implementation and identity

Update the root, native development and independent reference toolchains;
native host version/commit, source profile guard, workflow checks and selected
Standard payload identity. Profile /53 identifies the migration.
Update the canonical v7 header with an explicit user-authorized amendment;
preserve historical RC4 prose/receipts as provenance. The adoption registry
retains the original byte-identical upload separately and pins the exact amended
bytes. The native source guard now verifies this reference before building.

The Standard roster stays at 313 declarations /18 classes /54 instances.
Changing its pinned-toolchain field intentionally changes both canonical digests.
The strict digest guard must first report the new values; repinning follows
review, never automatic acceptance. Qualification is **pending**.

The preceding quoting run compiled and passed the native oracle, official kernel,
semantic/search/refusal gates and project emission, but its Wasm observation
generator only supported numeric/Boolean values. Extend that shared generator
with PSCV0 String literals and String equality without removing any observations.
This is required to run the already-added quoting cases across targets.

## Reference-first development rule

Before designing, implementing or redesigning any substantial feature:

1. Read the corresponding official sources and relevant tests at this exact pin.
2. Identify algorithms, data structures, semantics, invariants and optimizations.
3. Compare those mechanisms with the whole affected PSC0 subsystem.
4. Choose the simplest correct and maintainable adaptation for the selected scope.
5. Implement coherent capabilities and validate against Lean with focused
   conformance/differential evidence, then the existing integration gates.
6. Record important decisions, source/test links and attribution. Preserve
   upstream licenses when code is adapted.

Apply throughout M0–M5, A–E, C5 and future work. Historical compatibility is not
a reason to retain incorrect, duplicated or obsolete internal architecture.
The user still excludes pskernel-core and self-hosting from development/validation.
