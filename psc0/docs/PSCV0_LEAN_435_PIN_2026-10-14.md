## Reference-first development rule

Before designing, implementing or redesigning any substantial feature:

1. Read the corresponding official sources and relevant tests at this exact pin.
2. Identify algorithms, data structures, semantics, invariants and optimizations.
3. Compare those mechanisms with the whole affected PSC0 subsystem.
4. Choose the simplest correct and maintainable adaptation for the selected scope.
5. Implement coherent capabilities and validate against Lean with focused
   conformance/differential evidence, then the existing integration gates.
6. Record important decisions, source/test links and attribution. Preserve
   upstream licenses when code is adapted.

Apply throughout M0–M5, A–E, C5 and future work. Historical compatibility is not
a reason to retain incorrect, duplicated or obsolete internal architecture.
The user still excludes pskernel-core and self-hosting from development/validation.
