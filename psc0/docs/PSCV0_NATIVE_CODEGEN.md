# Native runtime emission

The official native Lean host checks the prepared graph, erases it, and calls
psWithCheckedIr on the exact immutable runtime IR before any selected backend.
Acceptance requires accepted AND traversalComplete. Reports are diagnostics,
not transferable permits. Raw backend lowering helpers do not claim admission.

Semantic names now retain their original spelling through erasure. Ps.Codegen.Names
creates a target view with consistent collision-free names across declarations,
types, binders, constructors and fields. It retains the semantic/output mapping;
target-only names never flow back into Core. Ordinary names and selected Unicode
letter ranges remain readable. Other spelling normalizations retain their origin.
This initial allocator prioritizes public declarations and preserves names after
unrelated noncolliding edits; collision-group canonicalization remains future work.

Ps.Codegen.Doc owns bounded compositional layout and UTF-8 generated byte ranges.
The first TS slice uses structured declaration and structure blocks. Existing TS
tail-loop/expression/inductive printers and inline runtime support remain reused;
complete structured TS expression printing and runtime extraction are later work.
Generated ranges identify semantic declarations through the symbol map; original
source-span/comment anchoring is not yet implemented and is not fabricated.

PsEmissionArtifact is portable data; the native CLI owns file writes and
.origins.json serialization. Source Lean/ProofScript printing must retain
pre-erasure information and is a separate later milestone. No compiler-source
.ps translation or self-hosting is part of this path.

Validation reuses the compact native application, strict TypeScript build and
runtime assertions. A small direct boundary check refuses an invalid IR and
checks naming collisions, Unicode retention and declaration range bounds.

## Proposed next architecture

PSCV0_DIRECT_JS_WASM_ARCHITECTURE.md records the requested research/design after
qualified native profile 31. It extends this pipeline with artifact bundles,
source provenance/export ABI, shared structured ECMAScript emission for TS and
directJS, a typed directWasm path, and pre-erasure source reconstruction.
The existing byte-origin records are not debugger source maps. These additions
are proposed only; implementation is stopped at the class-output milestone.

Revision 2 extends the proposed directWasm output to a matching WIT world,
component WAT and component binary. The checked public API feeds both WIT and
Canonical ABI adapters. Internal GC data is separate from boundary linear
memory/resource lifetimes. Core-Wasm output remains explicitly labelled.
No compiler implementation changes accompany this research revision.
