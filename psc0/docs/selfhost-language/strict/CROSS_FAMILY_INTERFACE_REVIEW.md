## 2. The function, expression and machine induction is compatible

COMMON's function clause at index 0 is structural: it records callable form, actual identity and capture edges, not equal future results. At index n+1, semantic behavior and captured environments are required only at smaller indices. E is pointwise V; the relevant function edge strictly decreases that index. Finite data edges use finite structural recursion. C observes independently specified computations; it is not defined by assuming the compiler preserves them. [COMMON §1.3]

This matters at the EV/TS mutual call boundary. EV does not assume all registered functions correct and then pass that assertion to TS. A lambda constructs its actual capture association; a call obtains its callee and argument values, spends one semantic application event, and uses the lower-index body statement. TS-RUNNER then preserves that specific body's continuation relation through request, push/direct entry, return and permitted abort. Its ordinary generator-body case uses the same expression theorem at the already decreased index. Non-call expression and statement cases decrease through finite syntax; eager initialization additionally decreases the declaration prefix. [EV §§1,5–6,13; TS §§1,5,9,11]

The residual is part of each observation. If an initializer or operand returns at r, the next component starts at r, and earlier values/environments weaken to r. A map/fold callback spends from that current remainder and returns its residue to the helper; nested runner entry carries it back to the suspended outer continuation. No initial budget is copied into each operand, callback, worker or reentrant runner.

The index 0 higher-order counterexample is avoided: observing a body g(Unit) with no remaining application allowance stops before invoking g. A merely structural V^0 function cannot license a later exact Bool result. Both final EV and TS formulations use COMMON's corrected residual-result rule, including the possibility of a terminal non-call result at V^0. [COMMON §1.3; EV §1.1; TS §§1.1,5.3]

Ordinary source Except.error is related data. A compiler refusal is a compiler result; a declared abort abandons the continuation; defensive malformed/bounds/empty throws and diagnostic foreign probes do not redefine the source effect alphabet. The runner's lack of catch/finally and generator.throw is consistent with that abort-only domain. No packet imports a handler semantics that the others fail to implement. [COMMON §2.3; ER §6; EV §§1.3,4.4; TS §§4.2,5.1]

## 3. Cofinal composition and progress

The source/N, Core/IR and IR/JavaScript projections have different event schedules. N counts original source groups and recursive occurrences while identifying actual worker/readiness controls. GROUP refines a known flat call or partial capture sequence after each supplied Core operand, before the next operand is demanded. IJ counts original-IR calls, including an inserted completion/entry/bridge call that CI may identify as control. Equality of their finite index numbers is neither required nor generally true. [N §§6–7; GROUP §§6.3–6.4; ER §13.2]

A direct or partial entry does not postpone all Core prefix events until after all supplied operands. The residual-entry view records each already returned operand and immediate beta boundary; eliding a variable/literal capture does not remove that boundary. On final completion, the internal flat-entry transfer reaches the actual declaration body already identified by ENTRY-PREFIX. Its control can be administrative in CI; the body is still compared at the inherited lower index. No opaque global-function hypothesis is silently invoked a second time to bypass its charge.

For composition, take a finite observation and expand its identified origin/entry controls into the corresponding finite common-IR prefix. Choose budgets that cover that prefix and leave the desired result index. All-index related starting value families supply those budgets; downward closure supplies the smaller residuals. Reverse composition follows the corresponding finite-prefix map. A single finite-index input relation would not suffice for this argument. Neither same-n transitivity nor a constant conversion ratio between counts is claimed. [GROUP §6.4; ER §13.2]

The finite-prefix mapping also has concrete progress measures:

- N's actual state-lambda readiness contains no original branch/body/callback work. Under the delayed generated-recursor rule, obtaining its closure requires finite selection and binding; the earlier eager-readiness argument was already finite by strict structural-child descent.
- ER's major capture, constructor/field setup and record projections traverse finite syntax/metadata or existing immutable values. Binding an IH does not force its body; an actual use returns to the recursive/body simulation.
- GROUP's completion and entry setup consumes finite prefix/capture slots. Unit/fold control has a fixed finite setup; authored callback stages remain observed.
- EV's non-call syntax work is structurally finite. Primitive string/array loops have finite represented-input/range measures; callback invocation is an application boundary.
- TS scheduling either handles finite administration, pops a completed frame or reaches a logical application. Count decreases a proper stored-data subvalue. Every continuing direct tail edge consumes one original call, and every alias edge consumes two. Successful terminal branches return rather than silently beginning another loop iteration.

Thus no listed local implementation path can hide an infinite execution solely as unmatched administration. An infinite demanded body/callback computation remains in its independent computation relation. Resource exhaustion, physical stack use and unequal allocation are outside the successful-resource comparison; finiteness is not a practical time or heap bound. [TS §§5.4,7.2–7.3,8.3–8.5; EV §§4.4,13; GROUP §6.4]

## 4. Native empty-data boundary and recursive structures

ER §10.6 keeps two distinct claims. The general Core/IR computation rule demands an empty match's major and constructs no result from a nonexistent constructor. The pinned native ToLCNF empty-case path can omit that discriminator, so a theorem for arbitrary open divergent or aborting Empty producers would be unjustified.

CLOSED-EMPTY instead uses the domain already in COMMON §1.1. The source has no accepted partial/axiom/opaque/foreign escape, source arguments are canonical generated values/functions, and the valid ordered Core environment has positive finite data. ER defines source computability independently of emitted preservation and proves closure through typed functions, finite primitives, actual structural recursion, and N's state-worker construction. A reached typed Empty major would then terminate in a computable Empty value, which has no constructor clause. Such a point is unreachable in that closed domain. [ER §10.6; SOURCE-GATE; COMMON §§1.1–1.2]

This does not assert that the type Empty→A has no functions. Such functions can exist without an Empty argument. It does exclude treating an arbitrary divergent or throwing host Unit→Empty callback as a closed generated source value. Diagnostic host demand probes retain their separate purpose.

The same unreachability reasoning cannot excuse compilation coverage. ER §11's new recursive-record route compiles accepted functions over direct recursive structures, with exact parameter-plus-three saturation, full fields then IHs, one major record capture, and ordered projections. Used root/outer IHs retain §10's demand relation. Their lack of finite inputs does not justify discarding their IH lambdas or refusing the declaration. This route preserves the existing record representation and does not introduce a cyclic foreign value into the relation. [ER §§10–11; STRUCTURE-REVIEW]

## 5. Reserved-sort alpha leaf: exact valid-source resolution

N §3.1 explicitly proves ordinary named-reference selection; it does not assert that one-segment Prop/Type is resolved as a local by Term. The normalizer's generalized reference walk in Recursion 8b1 lines 286–305 instead uses the ordinary base resolver after its self check. The distinction must be accounted for.

The pinned native grammar excludes an unquoted single-segment Prop or Type binder/declaration name:

1. Native Parser/Term.lean registers Type and Prop as builtin term symbols, lines 136–145.
2. Parser/Basic.lean gives an equal-length registered keyword priority as an atom, lines 934–964. identFn requires identKind, lines 1298–1306.
3. Parser/Term/Basic.lean defines binderIdent as ident or the hole and uses it in explicit/implicit binders, lines 178 and 206–218. Parser/Command.lean's declId also requires ident, lines 124–127.
4. Native escaped identifiers do not create a counterexample in the current owned authoring intersection: the owned lexer has no quoted-identifier path and rejects the escape delimiters « and » (code points 171 and 187), which are outside its identifier and symbol forms. [NT, NB, NTB, NC, LX]

SPEC keeps PSC1-compatible .lean authoritative; the corresponding generated .ps retains its actual binder names. Therefore an original parameter/current declaration in this valid source-owned domain cannot have either exact unquoted sort identity. On a reserved one-segment reference, the normalizer cannot select an original parameter/current self with that name. An absent/global result stays textually unchanged; any unrelated dummy shadow is outside the original parameter-ID set. This completes the reserved-sort case separately from the ordinary alpha cases. The internal generated names likewise use their documented non-sort construction. [SPEC scope and §§1–2; N §§3–4]

**Do not misstate this as a portable admission guard.** The owned lexer labels Prop/Type identifiers; its binder parser and Sh1 binder worklist do not themselves refuse those names. A source-inspected owned-parser example with a runtime parameter named Type, a varying recursive state, and a branch let t : Type := Nat predicts a normalized-worker expected-sort refusal after the sort token is renamed. No native-valid mandatory witness or successfully admitted wrong-result witness was established. The native-invalid example neither blocks this declared valid-source proof nor proves correctness for all extra raw-parser inputs. No broader parser/native syntax equivalence is claimed. [LX, PC, SOURCE-GATE, TERM, REC]

This boundary is an existing authoring premise with exact parser support, not a newly invented whitelist or a corpus-only claim. If a future source capability admits escaped/reserved binder names, the normalizer needs the corresponding reserved-reference rule and a fresh proof; this review does not pre-authorize that extension.
