# Checked component and optional-provider dispatch

This host slice extends the unchanged qualified generated compiler. It does not
add a second source frontend or claim a new self-hosted compiler generation.

The default root retains the qualified JS/TS compiler executors and the genuine
official Lean 4.35 C++ checker compiled with Emscripten to linear-memory Wasm.
Rust and compiler-Wasm execution remain explicit optional bundles. Compiler-Wasm
continues to use GC.

## Two stages, with explicit identities

The host captures exact sources, runs a pinned actual G3 executor and validates
its complete candidate identity, origin counts and source/body relationship.
The generated compiler strictly validates original and transformed IR. The host
independently admits the exact canonical logical graph using official Lean,
before target preparation or transactional publication.

For component output, compilerTarget is wasm-core and final target is
wasm-component. A small host container encoder packages the exact GC core bytes
using the same canonical type/alias/lift/export section layout as the existing
owned component encoder. It does not lower or modify core instructions.
The optional pinned wasm-tools 1.254.0 validates both modules and reports the
component WIT; a closed parser requires exact Bool signatures, argument names,
export order and no imports/extra declarations. The public ABI is Bool only,
at most16 direct parameters. Other types, unsupported names and callback IO
refuse. No String component support is claimed by this particular dispatch path;
the preceding native String component path remains preserved.

For Python/PHP, compilerTarget is js and final target is python or php. The host
discards the preliminary JS emission and passes only the already admitted
specialized portable IR, exact public names and explicit scalar/dispatcher ABI
to an optional emit-only worker. This uses the same shared backend source as the
existing native compiler. The worker has no source frontend, checker or publisher.
It decodes tagged tuples with finite depth, requires exact round-trip equality
through the existing canonical encoder, strictly revalidates IR, and performs
the target's existing public ABI checks before emission.

A preliminary JS target plan is not assumed to work for every optional target.
The optional target rechecks and may refuse an unsupported ABI or emission.
No refusal falls back to JS, native source compilation, another provider or a
different checker. Receipts name both targets, the exact IR/source/request/
response hashes and optional package source identities.

## Optional package and runtime authority

The root pins every byte of each optional package in its trusted distribution.
Package JSON locates resources and is checked as data; arbitrary package entry
points are never imported. Self-declared hashes, additional fields or copied
receipts cannot acquire session admission/publication authority.
Packages are absent by default and require explicit installation.

New optional packages contain Linux x64 tools and are qualified only on the
actual Linux runner environment. Python includes isolated Python3.14.8; PHP
includes PHP8.5.11 with GMP and explicitly disables FFI during target checking.
Those versions retain the established minimum target profiles. No runtime is
downloaded or compiled during npm installation or a compiler request.
macOS/Windows/other architectures refuse this new native dispatch path until
their own package and execution evidence exists. The core package remains
platform-neutral; this is not a final universal-platform release.

The package-local C launcher uses fixed programs and argument modes, no shell.
It installs the Linux parent-death signal,4GiB address-space and8MiB stack bounds
before exec. The host binds parent identity and enforces240-second requests,
32MiB request/response bounds and before/after resource integrity. Independent
checking remains120seconds. Source, project, candidate and package metadata
cannot choose tools, SDK paths, admission providers or publication operations.

A pinned actual target consumer checks syntax and exact public API. Python
requires its emitted __all__; PHP requires exact returned API keys. Unsupported
IR, malformed tuples, noncanonical literal encodings, absent/tampered packages,
unexpected metadata, symlinks, invalid source and consumer failures all refuse.

## Publication and evidence

The same private single-use session and immutable transactional store publish all
seven targets. Both pointer layouts, precommit refusal, retained immutable paths,
sealed inventories, postcommit durability uncertainty and Linux publication
guards retain the preceding contract.

compile returns UTF-8 Python/PHP source or component hex with encoding
psc1-wasm-component-hex/1. build returns an immutable actual component binary or
Python/PHP module, plus the full session and provider provenance in its generation.
A manifest/readback hash is integrity evidence, not a new proof-checking authority.

The focused Linux suite installs offline with empty caches, disabled install
scripts and Node-only compiler execution PATH. It uses all four genuine G3
executors, the five real source corpus cases including modules, handlers,
collections, Unicode/large integers and ordinary loops, both grammars, explicit
callback IO, actual isolated target runtimes and actual Wasmtime component
execution. Refusals must preserve prior generation identities. The old checked
publication/application/kernel/type/negative gates remain required.

Qualification is pending until exact successful jobs and artifact identities are
recorded. Logical admission plus bounded IR/consumer checks is not a formal proof
of erasure, backend preservation or whole-program equivalence.
