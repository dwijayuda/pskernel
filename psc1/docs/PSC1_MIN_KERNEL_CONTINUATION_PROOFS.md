Choose field names and binder order once, document them in the constructor

Suggested rules:

- Let infers the value type `A`, checks/infer its body under `A :: locals`, and
  returns the body's type. Its semantic model extends locals with the actual
  interpretation of the checked value.
- Pair infers both fields and returns `prod A B`. First/second project only from
  a successfully inferred product. They do not accept arbitrary structure owners.
- Each injection carries the missing side's type annotation. Infer the supplied
  value and construct `sum A B`; do not infer a missing type from arbitrary input
  metadata or grant a conversion rule to make a case pass.
- Case checks a sum scrutinee, infers the left body under `A :: locals` and the
  right body under `B :: locals`, and requires the existing sound type equality
  to identify the branch result types. The result type cannot depend on the
  scrutinee or the selected constructor in this fragment.

Extend the actual `Denote` with Lean products and sums. For case, interpret the
checked scrutinee, split that semantic sum, extend the corresponding context
model with its payload, and invoke the induction hypothesis for that body.
For let, use the interpreted value directly. For projections, destruct the
interpreted pair. No unchecked evaluator, substitution procedure, general WHNF,
or general DefEq is needed for these simple typing rules.

1. Extend the executable type equality and prove every new successful branch

## 5. Explicit nondependent Nat/List recursion after the profile proof

The next useful complete fragment adds type code `list A`, literal/list
constructors, and typed recursors whose result type is fixed. This directly
exercises recursive computation while preserving the simple semantic model.

For a Nat recursor with result type `R`, check the major at Nat, the zero branch
at `R`, and the step body at `R` under locals
`R :: Nat :: locals`: variable zero is the induction result and variable one is
the predecessor. Its denotation is Lean Nat recursion, interpreting the step
under `consModel inductionResult (consModel predecessor localModel)`.

For a List recursor over `A` with result `R`, check the major at `list A`, the
nil branch at `R`, and the cons branch at `R` under
`R :: list A :: A :: locals`: induction result, tail, then head. Interpret it
with structural List recursion and exactly that context order.

The runtime checker does not need to evaluate an arbitrary input term while
checking these nondependent rules. Semantic recursion is in the proof's
interpretation. If a runtime evaluator is added for another purpose, keep its
termination, resource policy, and correctness theorem distinct from type-checker
consistency.

Required negative cases include a missing/mistyped induction hypothesis, swapped
step binders, a recursor on the wrong major type, wrong result annotation, a
branch that tries to escape its locals, and fuel exhaustion. Use in-domain kernel
arena patterns where applicable; reject out-of-domain recursors explicitly.

This does **not** establish arbitrary Lean recursor support. A canonical recursor
can have universe parameters, indices, multiple motives, dependent result types,
and generated argument order. Recognizing the spelling `Nat.rec` or `List.rec`
does not prove that those additional arguments are harmless. A restricted
canonical application needs a proved specialization to the explicit rule above.

## 6. The canonical bridge is a formal component, not a JSON wrapper

Build this before promoting canonical `min` or `dual`, and before adding a large
unconnected general kernel implementation. Preserve three distinct functions:

```text
bounded byte decoder:
  exact input bytes -> canonical declaration AST or explicit refusal
restricted elaborated-Core recognizer/translation:
  canonical AST + exact foundation/profile -> fragment AST or refusal
actual fragment checker:
  fragment AST -> accepted environment or refusal
```

Use a minimal formal byte/token grammar, a proved decoder, or a proved relation
between the existing decoder's success and that grammar. Encoding then decoding
one's own examples is not a theorem about the decoder accepting hostile input.
The real host must execute the verified route; an unproved second fast parser is
a new boundary, even when it passes the same tests.

Ingress requirements include byte/depth/node/declaration/name/number budgets,
full consumption, duplicate-key handling, integer grammar, UTF-8/string escape
semantics, and rejection of unknown fields/tags. Reject cycles, getters and
prototype-bearing objects before a generated API can receive them, or expose
only the bounded byte interface. Do not claim the current typed AST interface
already qualifies arbitrary JavaScript objects.

For the first canonical domain, accept only a deliberately closed simple type
grammar and its supported term forms. A Pi can become a simple arrow only when
its codomain translation proves independence from the bound term. Reject bound
variables in that closed type grammar; do not erase a dependency and keep the
term. Reject universe instances outside the declared profile, arbitrary type
aliases requiring delta conversion, unsupported literals, metadata, unknown
constants, and all other Core forms.

Translate structured names to positional constants with a proved injective
mapping, no shadowing, correct dependency order, and no forward reference. Preserve
the name, universe arguments, declared type, body, and admission kind in the
correspondence relation. Index-zero constants in the fragment mean the most
recent checked declaration, not the first declaration in the source stream.

Suggested theorem structure, with names illustrative:

```text
decode_success_is_well_formed:
  decode limits bytes = ok canonical -> WellFormedBytes limits bytes canonical

translate_environment_preserves_identity:
  translate profile canonical = ok fragment -> Corresponds canonical fragment

canonical_admission_has_model:
  decode limits bytes = ok canonical ->
  translate profile canonical = ok fragment ->
  psMinCheckEnvironment ... fragment = some checked ->
  CanonicalEnvironmentModel profile canonical
```

The last theorem needs more than correspondence by names: prove type/term
interpretation preservation under the translated contexts and constants. To
obtain a no-canonical-False corollary, prove that the exact canonical False
foundation entry denotes Empty and that its claimed proof is retained under its
original identity/type. The existing STLC theorem alone does not identify it.

Use byte equality or a proved structural equality when the theorem requires
identity. SHA-256 receipts are useful provenance evidence, but hash equality is
not a Lean proof that arbitrary source terms are equal. If host authority rests
only on a hash, identify the cryptographic assumption outside the formal theorem.

The current canonical encoder has relevant specific behavior:

- User axioms and raw partial declarations refuse.
- An inductive record carries its type, constructor types, parameter count, and
  level parameters. Separate constructor and recursor records are skipped because
  the destination checker reconstructs the checked declarations from the group.
- Definition reducibility heights are computed by the bridge. They are not
  permission to accept a new reduction rule or an unverified body.
- `ordinary-checked` opaque/partial handling retains a constructive logical
  witness and separately typed executable body. Do not use the witness's easy
  inhabitance as a proof that a different retained body was checked. Preserve
  the original source/body pairing and transformed/original strict IR checks.

Therefore a minimal checker for an inductive group must validate that group's
signature and reconstruct sound constructor/recursor declarations. It cannot
assume the omitted recursor checks were performed elsewhere, or ignore the group
while accepting later uses of its generated recursor.

## 7. Regular datatype declarations: use current R2 for the measured target

After the fixed List/product/sum rules and bridge are proved, consider a regular
first-order datatype signature profile. This is narrower and more achievable
than arbitrary Lean strictly positive inductives.

Initially allow one datatype per group, a fixed parameter telescope of simple
types, no indices, and a finite constructor list. Field codes may refer to a
parameter, a previously modelled closed type, products/sums already supported,
or a direct recursive field. Explicitly forbid recursion in a function domain,
nested recursive applications, mutual blocks, dependent constructor fields,
large elimination from Prop, and universe-polymorphic dependent motives until
their separate rules are proved. An empty constructor list must denote Empty;
do not manufacture an inhabitant to simplify environment construction.

Construct the datatype semantics from a concrete strictly positive encoding,
such as well-founded constructor trees with the nonrecursive payload in each
node and a finite family of recursively typed children. Prove that the signature
recognizer selects precisely this syntax. Do not write `Mu F` for an arbitrary
Lean function `F : Type -> Type` and assume its recursive occurrence is positive;
Lean cannot generally justify that declaration. Either use a concrete positive
code interpretation or a proved W-type construction.

For each accepted group, prove:

1. Signature well-scoping and freshness; parameter occurrences are uniform and
   the exact accepted recursive occurrences satisfy the chosen positive syntax.
2. Model existence for its type and all constructor types, including the empty
   datatype case and recursive fields.
3. A constructor interpretation with correct field order and parameter arity.
4. The generated recursor's type and computation equations, with every required
   induction hypothesis. A boolean positivity check without this model bridge
   does not establish consistency.
5. Sound `.proj` conversion only for a qualified structure shape: check the owner,
   constructor count, parameters, field index, major type, and field type. General
   dependent field projections remain outside this first profile.
6. Environment extension and every reduction/DefEq rule that consumes the new
   group. No unconstrained recursor metadata or source-supplied K rule is trusted.

The current audit's 308 inductive records are not evidence that all fit this
profile. Extract their parameter/index/field/recursor shapes first. A regular
source declaration can elaborate to a dependent recursor type. Prove any
specialization you use; do not drop generated logical declarations to obtain a
smaller reported closure.

## 8. Decision gate before dependent Pi, Prop, and universes

Do not treat a finite universe cap as a solution to dependent type theory.
`Type 0 : Type 0` is not an acceptable simplification. A semantic universe that
contains its own interpretation creates a size problem; term-level natural
universe levels also do not automatically select Lean's metalevel universe
hierarchy. An inductive code universe closed under arbitrary dependent Pi needs
its own positivity, size, and interpretation construction.

Before implementing dependent conversion, write a small formal design experiment
and compare these two credible routes:

| Route | Required evidence before adoption |
| --- | --- |
| Restricted direct dependent model | A precise calculus with stratified universes/Prop rules, a model construction with explicit hypotheses, substitution and environment lemmas, and one actual checker acceptance theorem for a nontrivial complete fragment. |
| Executable refinement to a proved checker | A pinned target such as con-leche verified mode; an exact translation/refinement relation; proof that the proposed runtime acceptance implies target acceptance; model correspondence for the exact admitted foundation; and an executable runtime closure that remains PSC1-supported. |

The con-leche model theorem is conditional on its `SetTheory` interface, including
an omega chain of Grothendieck universes. That model-existence premise is not a
line in `#print axioms`. Its theorem does not automatically cover code changes,
a new PSC1 implementation, new primitive pins, or a permissive decoder.

A verified reduction to con-leche does not require calling con-leche at runtime:
the executable minimal checker can remain standalone while its acceptance is
related to con-leche's mathematical function in the separate proof. However,
prove that relation. Do not replace it by a differential test, the official Lean
checker accepting examples, or a source translation with no implementation bridge.
The target's permitted foundation must actually admit this project's primitives;
do not assume arbitrary axioms are allowed merely because their types parse.

If the next dependency frontier needs full dependent universes/Prop before a
regular-data profile can make useful progress, stop expanding the STLC runtime
and perform this comparison. Keep the existing complete theorem as a qualified
baseline while prototyping a separate calculus. Do not accumulate a large
unproved implementation under its consistency label.

Any dependent route must address at least the following actual mechanisms:

- Context and simultaneous substitution, weakening, binder scope, and universe
  substitution; no informal reliance on parser-produced well-formed terms.
- Well-typed Pi formation with the chosen `max`/`imax` behavior, universe arity,
  fresh/declared parameters, and definitional equality of level instances.
- A separate Prop interpretation, proof irrelevance only in its valid scope,
  and the exact allowed elimination restrictions. Equating proofs of a common
  proposition is different from equating arbitrary proposition types.
- Beta/zeta/delta/iota/projection reduction soundness and the actual algorithm's
  successful conversion path. Resource exhaustion must never be a proof of
  equality or a route to unchecked admission.
- A modelled initial foundation and preservation under definitions, opaque
  declarations, inductives, and every supported recursor.

## 9. Build a complete primitive/foundation ledger

The prelude is code, not a trusted sentence saying "standard library". Inspect
the exact current owned prelude, the separately replayed official-provider
prelude, the closure's used-axiom set, and all reduction code. The provider
currently converts permitted prelude axiom entries into safe Lean axiom
declarations; refusing user axioms does not remove those logical assumptions.

Create one machine-readable row per admitted foundational declaration:

```text
structured name; level parameters; exact declared type/identity
origin and canonical/prelude byte identity
imported vs transitively used by this compiler graph
semantic carrier/value and required existence theorem
all checker reductions/definitional equations for this constant
proof that the value has the declared interpreted type
proof of each implemented reduction equation
runtime/backend interpretation and its separately stated evidence
unsupported input/resource behavior
```

Cover every row; do not replace 60 individual obligations with a global
`foundationSound : Prop` assumption and announce consistency of the foundation.
If the main theorem is conditional on such a supplied model, label the result
conditional and list every undisclosed obligation rather than hiding it behind
a class instance.

Suggested partitions for the actual declarations are:

- Nat/Int and arithmetic/conversions: intended unbounded or explicitly modular
  carriers, literal interpretation, totality, and every pinned numeric reduction.
- Bool/Unit, List/Option/Except/Prod: actual datatype/constructor/recursor models;
  a pinned type axiom and an inductive with the same spelling are different
  admission mechanisms.
- String/Char and byte positions: exact scalar/UTF-8/position behavior. Length,
  byte size, byte-index movement, and character indexing are not interchangeable.
- Array: polymorphic carrier and empty/size/push/defaulted-get/set/map/fold
  functions, with their precise types and any supported computation equations.
- Eq/Decidable/ite: universe-polymorphic/dependent type semantics, the equality
  relation, decisions, and conditional values. These are not just runtime booleans.
- Any quotation, quotient, standard logical axiom, unsafe/partial primitive, or
  external declaration that appears in the refreshed dependency graph: either
  provide its actual interpretation and rule proof or explicitly reject it.

For an opaque constant with no computation rule, constructing a suitable typed
value can suffice for consistency. It need not prove the intended application
behavior. Once the checker reduces that constant, its model must satisfy those
equations too. Do not use arbitrary constant functions to model an arithmetic or
string primitive whose reductions the checker actually performs.

Prune unused foundation declarations only after proving the complete dependency
subset, including references in types. Keep its own exact profile identity.
Do not change the official provider's default prelude or report that the omitted
declarations were checked. The minimal profile can model a smaller admitted
environment while the official verifier preserves broader compatibility.

## 10. Reduction and implementation bridges before optimization

When conversion becomes necessary, strengthen the environment model to retain
each checked definition's body and its denotation equation. Then prove the actual
primitive reduction functions sound, and compose those lemmas into the actual
successful WHNF/DefEq/inference/admission path.

Useful theorem shapes are:

```text
reduce_success_preserves_interpretation:
  reduce fuel env term = some result -> related interpretations term result

defeq_true_is_semantically_equal:
  defeq fuel env context left right = true -> semantic type equality

check_environment_extends_model:
  checkEnvironment ... initial declarations = ok final ->
  Model initial -> Model final
```

Specify the typing preconditions and equality/transport relation in these
statements; "related interpretations" cannot remain an undefined assumption.
Dependent conversion may need both type interpretation equality and term
transport. The current simple `Ty` equality theorem is not that result.

Begin with immutable trees and a fuelled baseline. Introduce sharing, an arena,
caches, or destructive updates only when profiling a qualified domain identifies
the cost. An optimized representation needs a decoding/refinement invariant and
a proof connecting its success to the already proved checker. A cache hit must
be justified by its key, environment identity, scope, and invariant; a previous
success receipt is not a semantic cache theorem.

The con-ron proof architecture is a useful precedent for composing a pure checker,
an arena representation, and an extracted implementation. It also records
translation/IO/driver assumptions that remain outside its capstones. Copy that
precision of boundary, not its assurance label or presumed performance.

## 11. Source portability and Linux-only execution recipe

All builds, tests, proof checks, and benchmarks run in Linux GitHub Actions.
Do not use Desktop Commander or local build/test commands. Draft edits as allowed
by the active task, but treat freshly fetched GitHub source as repository truth.

The historical self-host source profile is narrower than the whole current
frontend. The successful kernel source deliberately uses:

- Flat prefixed names; no runtime `namespace`, `open`, or `end` commands.
- Binder-form inductive constructors such as `| arr (domain : PsMinTy)
  (result : PsMinTy)`, rather than `| arr : ...` result signatures.
- Explicit `Option.none`, `Option.some`, `List.nil`, and `List.cons` in expressions
  and patterns. Infix `::` expressions were rejected by the tested profile.
- Unary, flat constructor matches; expand nested patterns into separate matches.
- `Nat.zero`/`0` and successor patterns; vector dispatch uses `Nat.beq` and `if`
  instead of match patterns on numerals greater than zero.
- Explicit `if` logic; avoid adding boolean infix, convenient syntax, or derived
  instances merely because native Lean accepts them.

Do not expand the compiler's historical source policy to get one small kernel
module through it. Use the supported subset unless a separate measured compiler
change is necessary and independently qualified.

Proof source may use full Lean. Keep runtime imports free of proof modules and
register new runtime/proof roots explicitly in the respective Lake projects.
The proof project must import the actual executable file in place, rather than
compile a second hand-maintained copy.

The dedicated workflow is `.github/workflows/psc1-minkernel.yml`. Its Linux lanes
perform these commands with the repository pin and existing host limits:

```text
psc1/proofs/pskernel-min:
  lean --version
  lake build                       # retains proof.log and #print axioms

psc1/packages/pskernel-min:
  lake build minkernel_tests
  .lake/build/bin/minkernel_tests

psc1:
  node scripts/minkernel-mode-tests.mjs
  lake build psc1_sh1_compile psc1_independent_checker
    psc1_source_census_probe psc2_joint_closure_inventory
  node scripts/minkernel-portability.mjs
  node scripts/minkernel-closure-audit.mjs
```

These are workflow commands, not permission to run them locally. Read the live
workflow before copying target names or tool versions. The proof pin at the
qualified checkpoint is Lean 4.35.0,
`eb6cafb7290e8bd5f2937522d8d804f58f02bafc`.

For every proof change, print axioms of each acceptance bridge and the final
theorems. Reject `sorryAx`, admitted placeholders, arbitrary new axioms, unsafe
escapes, unchecked declarations, and hidden native/reference-checker calls.
The current report is `[propext]`; if a legitimate new proof requires another
standard Lean dependency, inspect and document it explicitly rather than relaxing
the guard to accept any axiom list. Audit runtime replacement attributes and IO
escapes separately because `#print axioms` alone cannot detect them.

If a proof fails, fix the proof or narrow the implemented fragment; never weaken
the statement to a tautological rejection predicate. If portability fails,
correct the source/API registration rather than substitute a native artifact
and claim a generated checker ran. Retain failed runs as historical diagnostics
and cite only terminal passing runs for qualification.

## 12. Promotion and self-hosting gates

Before a host-controlled canonical `min` profile may accept:

1. Its exact admitted foundation, byte grammar, canonical translation, runtime
   rules, and implementation-to-model bridge are complete for that domain.
2. The actual generated standalone checker accepts/rejects the retained canonical
   corpus with no official/native fallback, cached admission, or source-selected
   authority. The host validates executable/profile identities.
3. Refusals distinguish unsupported profile, malformed input, semantic failure,
   and exhausted resources. Every exhaustion path refuses and remains deterministic.
4. Negative/adversarial and official-common-domain agreement tests pass in Linux;
   source, manifest, exact admission/body identities, strict IR, and existing
   publication/resource/ABI safeguards remain intact.
5. The theorem/trust report names the proven source and any remaining generated
   execution assumptions. An empirical translation chain is labelled empirical.

Only then replace the current unconditional canonical refusal for that explicit
profile. Preserve official Lean Wasm as the default. A `dual` request requires
both checkers to accept the same declarations in a proved common domain; an
unsupported minimal result is not permission to return the official result as
dual success.

Before minimal-kernel compiler G1/G2/G3 qualification:

- Check the complete fresh executable compiler source graph, including the
  kernel runtime sources if they belong to that cycle, under the generated
  minimal checker and its complete modelled foundation.
- Prove/validate exact source-to-admission/body pairing and retain the declared
  unsupported boundary. A list of accepted simple queries is not graph coverage.
- Instrument actual checker invocation and identities so native calls, cache
  bypasses, frozen receipts, or hidden delegation cannot satisfy this gate.
- Build genuine generations and compare the project's existing exact fixed-point
  criteria. Do not relabel historical official-checked frozen G3 executables.
- Run relevant Practical Core/backend/source/installed regressions and preserve
  independent official native/Wasm checking on its original architecture.

If a mathematical obligation prevents the next promotion, preserve the complete
smaller theorem and identify the precise missing rule/model/bridge with its first
real dependency witness. That is useful unfinished work. "The rest is difficult"
or "tests passed" is not an architectural blocker or a consistency proof.

Update `psc1/AI_WORK_STATE.md` without erasing concurrent project state, and update
the dedicated minimal-kernel work/proof/coverage documents. Keep a machine-readable
receipt with:

```text
runtime/proof/decoder/translation/profile identities
exact admitted foundation and covered canonical domain

```

Benchmark equivalent domains. Separate checker work from process launch, imports,

before measuring a relevant larger qualified domain.

Keep generated payloads and proof artifacts out of the executable source import
closure. Do not merge into the parent, publish npm packages, weaken immutable
publication, or broaden trust merely to finish a checklist.
