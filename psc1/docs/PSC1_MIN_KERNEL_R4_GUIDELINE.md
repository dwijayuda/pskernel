## Public boundary and accepted source grammar

The host supplies the actual generated module to the trusted research factory.
An untrusted caller supplies only an exact-prototype Uint8Array. The host takes
an intrinsic snapshot before parsing. Objects, arrays, Buffer, DataView,
subclasses, proxies and shared backing buffers refuse; caller length/iterator
getters are ignored. JSON.parse only proposes typed syntax. The source-owned
verifier binds every original byte to that candidate and requires complete input
consumption. There is no official-provider fallback.

Canonical JSON v2 uses the repository's compact field order, without a final
newline. Unknown, duplicate or reordered fields, extra metadata, trailing input,
noncanonical decimal spellings, escapes and unsupported universes refuse.
Names retain structured string/numeric components: a literal dot differs from
a namespace separator. ASCII components are 32–126 except quote and backslash.

The source language supports safe universe-closed definitions; the canonical
empty proposition, Unit, Nat and Bool; closed nondependent arrows; monomorphic
List/Option; scoped variables, prior globals, literals, annotated lambdas,
applications and lets; the selected primitive schemas; and regular data described
below. Regular-height metadata is retained and grants no conversion authority.
There is no arbitrary user axiom, theorem/opaque declaration or dependent alias.

List/Option and their constructors use empty universe-argument lists in the pinned
PSC1 prelude. Their element must be source Type-sorted. A Pi has its codomain
sort: False→False is a proposition, while False→Nat is Type-sorted. The level-1
conditional and recursor result must also be Type-sorted. Valid level-0
proposition eliminations can refuse as outside this profile.

The only proof/decision macro is the exact full ite.{1} spine with Eq.{1} Bool
left right and Bool.decEq left right, including identical operand ASTs and retained
annotations/levels. Arbitrary proof/decision erasure is unavailable.

R4B admits a single Type-0 family per group, with no level parameters, parameters
or indices. A constructor field is direct self or a closed ground type from
earlier groups. Nested/negative self, indexed/mutual groups and Prop families
refuse. Constructor names/types are retained and postchecked against actual
ambient signatures. Family/constructor/generated recursor names share one fresh
namespace with definitions; reserved foundation roots cannot be shadowed.

Nat/List/Option and owned regular recursors require exact universe instances,
explicit closed type arguments where applicable, and constant motives whose
source domain matches exactly. A regular recursor may return a carrier declared after its selected family,
provided that carrier is already visible at the use site. Projections retain owner/index/major syntax; the checked
descriptor must have one constructor, a real field and the matching major type.

Closed type grammar excludes bound variables everywhere. Conversion is
structural type-code equality with a semantic proof. There is no general
beta/delta type-conversion engine or dependent-alias acceptance.

## Architectural mechanism and proved boundary

R4A uses source-owned exact re-encoding and comparison for a small domain.
R4B streams canonical punctuation, names, expressions and base-ten numeric tokens.
The independent Wire grammar retains actual natural values and complete packet
structure; parser output and a checker-success Boolean are not semantic premises.

Source translation has independent type/term/environment image grammars.
The regular proof records original constructor types and positive field
descriptors, source declaration order, freshness reservations and exact nominal
slots. Ordered plans connect name lookup to the actual registry entry.

RegularIngressOperational defines a separate PsMinRegCoreTerm. Its ordinary
atoms use actual R3 checking and the proved canonical foundation/projection
models. Its regular recursor keeps the result code in the full ambient registry.
Field domains are lifted from the selected family's earlier prefix. The model
folds the existing positive carrier into the actual ambient result type, and
prefix/field/branch lemmas justify its casts. Existing R2/R3 runtime and proofs
remain unchanged.

The source semantics give concrete meanings to primitives, conditional spines,
constructors, recursors and projections. SourceHistory interprets each original
body in its declaration-time name/value context. The byte_admission_source_model
capstone composes candidate identity, complete wire derivation and those source
body values. byte_admission_consistent rules out a declaration of the exact
canonical empty proposition. The final models instantiate actual R2/R3 and
ambient interpretations; they do not assume an arbitrary foundation model.

The generic intermediate evaluation interfaces are proof organization, not
extra trusted models. The legacy prefix-lowering comparison is proof-only and
excluded from the connected runtime.

Two real defects guided the implementation. Earlier finite R4A positives missed
the Prop/Type boundary; explicit source-sort guards and six counterexample probes
fixed it before qualification at a90054c. In R4B, lowering first repaired
psMinRegLiftTy's prefix result. psMinCoreConditionalView then exposed a valid
later-carrier result that R2's domain cannot express. The separate ambient layer
solves that mechanism without changing R2 or adding a fixture/name/hash rule.

| Numeric name components | <4096 | <4096 |
| Translation entry / expression fuel | 128 / 64 | 512 / 256 |
| Inference / definition fuel | 128 / 128 | 512 / 512 |

R4B bounds each constructor list by 512. Limits are ceilings; additional
conservative fuel checks can refuse a well-typed packet within them.
The boundary suite accepts 512 definitions, expression depth 256, 512
constructors and 512 empty groups, and refuses their tested over-limit variants.
A 512-group packet whose oldest family needs a ground-type check deliberately
refuses when registry-validation fuel exhausts; the official checker accepts it.
No budget or guard was weakened to make that packet pass.

Both host processes retain a **256 MiB V8 old-space cap**; this is not a total RSS
bound or complexity theorem. At the qualified run, generated self-admission took
about 31.7 s inside the call and reported maxRSS 301416 KiB. Resource probes
reported maxRSS 154984 KiB. These are individual Linux observations, not a
performance guarantee. Workflow proof/portability timeouts remain 10/20 minutes.

The connected runtime is RegularProfile, RegularCheck, OperationalProfile,
OperationalCheck, CoreBytes, CoreIngress, RegularIngressProfile,
RegularIngressOperational, RegularIngressCheck and RegularIngressBytes.
It contains no String/Char operation in those explicit sources. Test vectors,
Lean/JSON/IO native harnesses, host JavaScript, compiler/emitter and shared
generated runtime remain distinct scopes. The old Check-only 12 records,
R2's 37, R3's 56, R4A's 103 and R4B's 206 are different connected-source censuses.
