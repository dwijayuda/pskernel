## 4. Recursor result types and the scope trap

The recursor positions are derived from actual prelude metadata or the source
origin plus owned inductive declaration, not string suffix guesses:

| Worker record | Recursor applications |
| ---: | --- |
| 3 | `Nat.rec` ×1, `PsMinTy.rec` ×5 |
| 5 | `List.rec` ×1, `Nat.rec` ×1 |
| 7 | `Nat.rec` ×1, `PsMinExpr.rec` ×1, `Option.rec` ×3, `PsMinTy.rec` ×1 |
| 9 | `List.rec` ×1, `Nat.rec` ×1, `Option.rec` ×1 |

Read-only inspection of the retained motive ASTs gives these seven distinct
closed result shapes. This enumeration is explanatory inspection; the CI report
guards the weaker binder-aware `no-major-reference` classification:

```text
Bool
PsMinTy -> PsMinTy -> Bool
Option PsMinTy
Nat -> Option PsMinTy
List PsMinTy -> PsMinExpr -> Option PsMinTy
Option (List PsMinTy)
Nat -> List PsMinTy -> Option (List PsMinTy)
```

Measured List parameters are `PsMinTy` and `PsMinDeclaration`; measured Option
parameters in these recursor spines are `PsMinTy`. The next implementation should
recognize a structurally specified family of closed type codes, then enumerate
and bound the instances it needs. The seven results are a target workload, never
an acceptance whitelist of these expressions or of these 12 records.

Removing a binder is not generally the identity on its body. In context
`Gamma, x`, a body referencing an outer variable can contain `bvar 1` without
containing `bvar 0`. Removing `x` must lower that reference to `bvar 0`. Under a
nested lambda, the removed binder is at depth 1, not depth 0. Pi/lambda domains
and let types/values remain outside their newly introduced binder.

The new checked theorem concerns the actual existing Core operations:

```lean
psExprInstantiateAt replacement depth
  (psExprLiftBVars 1 depth expression) = expression

psExprInstantiate1 (psExprLiftBVars 1 0 result) major = result
```

`Ps.MinKernel.CoreScope.instantiate_lift`, `constant_motive_body` and
`constant_motive_argument_irrelevant` each print exactly `[propext]` in Linux CI.
The theorem handles every `PsExpr` constructor and arbitrary open expressions;
it adds no well-formedness or closedness premise. Its quantification over
arbitrary syntax is a syntactic inverse law, not a statement that malformed syntax
is well typed. The proof imports `Ps.Core.Subst`; it does not define a parallel
substitution model or alter the runtime.

For an arbitrary observed motive body `body`, we still need a proved recognizer
that constructs `result` and establishes
`body = psExprLiftBVars 1 0 result`. The theorem above proves substitution
independence only after that equation. The diagnostic's Boolean scope result
does not supply the equation, result typing, a reduction-preservation theorem or
recursor soundness.

```text
Bool       : Type
Bool.true  : Bool
Bool.false : Bool
```

These are sketches of retained ASTs, not authoritative replacements for them.
The prelude's `ite` value uses the actual `Decidable.rec` and
`_psc1OrderFalse`. A future proof must interpret its declared type and exact body.
Seeing an `ite` head does not justify lowering it to an arbitrary Bool branch.

There are two coherent possible proof scopes; choose and state one:

1. **A finite instance profile.** Check every source occurrence, specialize only
   closed permitted type instances, translate all uses of the permitted primitive
   spine, and prove a model for the resulting specified source profile. Prove the
   profile recognizer and each instance translation. Do not describe this as a
   model of the unmodified generic 115-entry environment.
2. **A foundation/environment model.** Interpret generic allowed declarations,
   their levels, propositions, datatype rules and bodies, and prove all rules of
   the admitted source calculus preserve that model. This is the broader route.

For the finite instance route, Bool as a two-element type, the two constants,
equality, and Boolean equality decision have straightforward candidate meanings.
They still need proofs attached to exact source declarations and applications.
For `ite`, establish the actual proposition/decision pair, both branch types,
the chosen result sort, and preservation of the body's elimination rules.
Do not invent an Eq eliminator, erase proof arguments silently, or use the host's
runtime branch behavior as evidence of logical validity.

Representing closed object type codes in an ambient Lean universe is reasonable.
It does not permit `Type : Type` in the object calculus or a uniform interpretation
of arbitrary `Sort u` into itself. Universe codes, admitted instances and any
ambient size assumptions must be explicit in the theorem.

## 6. Selected next target and bounded implementation sequence

**Recommendation:** continue route A, direct modeling, for a restricted regular-data
and constant-motive profile of the checker's own Core. Keep the full 124-module
dependent architecture decision open. This recommendation follows the measured
closed motives and regular fields; it is not a new consistency theorem.

Do not vendor con-leche or enlarge the runtime to general dependent conversion
for this batch. The pinned research still exposes arbitrary-axiom refusal,
self-hostability obstacles and the List/String representation mismatch. Use the
[research appendix](PSC1_MIN_KERNEL_CONTINUATION_RESEARCH.md) if the direct route
meets a genuine counterexample requiring a different full-checking architecture.

The next coherent batches are sequential:

### R1. Proved executable removal of an unused binder (qualified at8b33b3a1)

Add a safe source-subset function, provisionally `psMinLowerUnusedBinder`, returning
`Option PsExpr`. At cutoff `d`, reject `bvar d`, leave indices below `d`, and lower
indices above it by one. Traverse every actual Core constructor with the same
binder conventions as `Subst.lean`. Unsupported forms may be refused, but every
successful result needs the theorem below. Use a decreasing structural argument
or explicit fuel; exhaustion refuses.

Target statements, with final signatures matched to the actual function:

```lean
lowerUnused depth body = some result ->
  psExprLiftBVars 1 depth result = body

lowerUnused 0 body = some result ->
  psExprInstantiate1 body major = result
```

Derive the second statement from the first and `instantiate_lift`; do not repeat
a divergent substitution implementation. The first statement is enough for
sound acceptance; completeness can be a separately scoped theorem. A fuelled
version must quantify over the actual successful fuelled call. No general
normalizer or semantic recursor rule is required to finish R1. Successful lowering
is a syntax transformation result, never logical admission. In particular, a
standalone helper may preserve free/meta variables while canonical ingress must
still reject them under its own proved contract.

Meaningful negative cases include a removed binder under nested lambdas, a use in
a binder domain, a let type/value versus let body, and a dangling variable after
lowering at the separate ingress scope check. The lowering function itself may
return open results; its inverse law must hold for them. Positive cases include
open outer references and every Core constructor
the function supports. Native and PSC1-generated results must agree on the same
source vectors. Keep these tests in Linux Actions; do not execute them locally.

Initially place the helper in a separate experimental source-subset module; keep
the current STLC acceptance function intact. Importing actual Core syntax adds a
dependency closure, so measure its imports and emitted admissions anew. The
one-module/93-line count applies to the current checker, not automatically to
the future helper or a connected canonical checker. Proof imports of Subst stay
in the independent proof project.

### R2. Closed type codes and regular-data descriptors

Define the permitted grammar explicitly: closed ground data, arrows, and bounded
List/Option instances; ordered first-order datatype groups with no indices or
mutual recursion initially, fields using previous groups or direct positive self
references. Reject function-field recursion, negative positions, free type
variables, altered universe arities and unsupported indices. State whether the
profile accepts only known host-owned primitive declarations and what proves
their exact identity/type/body match.

Prove descriptor validity implies a concrete model, constructor typing and a
semantic interpretation of generated eliminators. Derive recursor descriptors
from checked group data; compiler-origin metadata and `.rec` suffixes cannot
authorize admission. Preserve a map between exact source names and the model's
slots, including fresh generated members and reserved-name collisions.

Then check one actual recursor application from the retained Core, with all
parameters, level instances, motive, minors, recursive hypotheses and major.
Use R1 to justify constant-motive specialization. Prove typing preservation and
the used iota equations, not only a syntactic no-reference property. Cover altered
minor argument order/type and forged constructor/recursor metadata with refusals.

### R3. Finish the runtime profile and its acceptance-to-model bridge

Add checked lets and the precise declaration projection rules, then the selected
foundation instance semantics. Extend the real success-to-model invariant over
the actual declaration fold. For delta conversion, retain a body/evaluation
invariant for earlier definitions; a type-only environment invariant is too weak
to justify arbitrary unfolding. Keep termination/exhaustion and conversion
soundness explicit.

An acceptable milestone is a proved recognizer/translator for a defined infinite
family with the actual 12-record workload as one test. A hash whitelist or a
checker for only these frozen names/records is not acceptable. Do not call
coverage complete until the entire required selected graph and its permitted
foundation/profile are checked by the generated executable without fallback.

### R4. Canonical ingress, generated-code boundary, then self-check

Compose bounded exact bytes-to-AST decoding, exact profile translation, and actual
checker success-to-model. Preserve declaration ordering, names, levels, bodies,
generated members and ordinary executable/logical identity. A semantic theorem
for typed Lean values does not validate arbitrary JS objects or JSON.

Record whether executable refinement is proved or remains an explicit compiler/
runtime trust boundary. Finite native/generated agreement never silently closes
it. Then qualify generated MinKernel admission of its complete implementation,
expand the supported whole-compiler frontier, and only after sufficient coverage
run min-checked G1/G2/G3 under the existing byte fixed-point contract.
