# PSC1 Practical Core v1 decisions

Baseline: `da880d864ca5f9e35729255fd7e4f8a17953cd39` (PR #166). Semantic authority: official Lean 4.35.0, commit `eb6cafb7290e8bd5f2937522d8d804f58f02bafc`. The baseline records selected cases in 13 families; typed IO is missing. All fourteen full families remain incomplete. These decisions define a finite prospective v1 contract; they do not relabel historical partial evidence as completion.

## Selection and rationale

Keep all fourteen families in bounded roles. Essential Core Standard owns pure data/functions, checked numerical meaning, efficient persistent collections, symbol identity and predictable elaboration. Practical syntax adds structured sequencing/control over checked definitions. CompilerM is an optional checked standard-library effect, not a new logical kernel. IO and foreign effects use explicit typed host capabilities. Broad metaprogramming, arbitrary effects/iterators, references and advanced dependent syntax may be deferred without making ordinary compiler programming impractical.

## Retained language outside the fourteen additions

Preserve existing named definitions/theorems, supported explicit/implicit binders, dependent Pi terms, lambda/application, literals, immutable lets, Bool conditions, bounded Type0 structures/inductives/matches, structural recursion, captured imports and proof erasure. Do not reduce working language functionality merely to shrink the plan. User universe/class/instance/tactic/macro/mutual declarations, indexed inductive source and general dependent pattern matching are not implied by current Core constructors. Inventory compiler use before selecting additions.

## Cross-language comparison

Lean establishes PSC1's exact logical and pure functional meaning; its checked Except implementation already expresses typed errors with ordinary data and bind. This supports syntax over checked definitions instead of new trusted effects. Lean's general Monad/typeclass machinery is broader than the bounded compiler needs, so retain an extensible library seam without making its full surface a first-self-host prerequisite.

Go demonstrates that compact declarations, inference and structured iteration can sustain practical general-purpose development. Rust supplies a useful model for explicit mutation, typed results, owned values and precise loop evaluation. PSC1 should reuse their clarity rather than import Go's concurrency or Rust's borrowing/type-system complexity into v1.

TypeScript contextual typing supports keeping local/call inference predictable and annotation-friendly; its unchecked any behavior should not be imported into checked Core. Python/PHP show familiar control and convenient ecosystem reuse, but their host exception/alias/numeric rules must not replace PSC1's typed error values, persistent arrays and exact integers. Interop therefore requires explicit adapters and contracts rather than assuming host semantics.

These are design inferences from primary references, not claims that the languages have identical capabilities: [pinned Lean Except](https://github.com/leanprover/lean4/blob/eb6cafb7290e8bd5f2937522d8d804f58f02bafc/src/Init/Control/Except.lean), [Go specification](https://go.dev/ref/spec), [Rust loop reference](https://doc.rust-lang.org/reference/expressions/loop-expr.html), [TypeScript contextual typing](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html), [Python compound statements](https://docs.python.org/3/reference/compound_stmts.html), [PHP official error-handling source](https://github.com/php/doc-en/blob/master/language/error-handling.xml). Use pinned Lean source for version-sensitive semantics; online latest Lean documentation currently describes a later release.

## Finite completion gate

A family becomes selected-v1 complete only after its explicit finite case list passes both independently authored source grammars, canonical independent admission, strict IR, every relevant backend and required refusals. Record internal execution separately from public marshalling. Include cross-feature cases for scope, mutation/return/handler/loop interactions, aliasing, exact numbers and Unicode; a combined Bool export may observe these internals but cannot qualify aggregate ABI.

Generate per-case CI receipts and validate their full required cross product. Proof/type-only cases explicitly use admission/erasure evidence instead of artificial runtime tests. Preserve exact source hashes, commit/tested-merge/run/tool identities and historical receipts. No percentage or broad complete label substitutes for executable coverage.

Priorities: repair compositional typed handlers; census the actual compiler closure; close required efficient collection/control and Rust owned-closure gaps; implement typed host boundary; complete JS then Rust generated compiler execution and generation comparison. Optional syntax, broad interop and automatic refactoring must not delay first compiler-only self-host without a dependency demonstrated by the census.
