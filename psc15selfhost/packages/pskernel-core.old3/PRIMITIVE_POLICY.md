# Fixed intrinsic policy: String literals

This private checkpoint introduces a fixed source-owned `String : Type` intrinsic after the existing source-checked Nat bootstrap. It is a kernel primitive rule, not an ordinary user definition or a claim that the full logical definition of Lean String has been reconstructed.

`BuiltinText.lean` constructs the exact full name, checks that it is fresh, and installs the internal String marker. Its only literal rules are: a well-formed Unicode-scalar UTF-8 byte sequence has type String, and two such literals convert exactly when their bytes agree. Beta, zeta and transparent delta can expose these literals. No Unicode normalization, replacement-character decoding, truncation or embedded-zero termination is performed.

The generated transition machine rejects non-byte naturals, overlong encodings, stray or missing continuation bytes, surrogate encodings and scalar values above U+10FFFF. Byte scanning, range comparisons, name lookup, typing, normalization and conversion are charged to the enclosing budget. Exhaustion is never a partial success.

The wire adapter encodes well-formed host strings into the generated byte constructors. It does not decide literal typing or equality and cannot provide intrinsic markers. A same-spelled ordinary constant, unit, record or caller-supplied metadata object grants no literal authority. Ordinary declaration admission rejects the internal marker. Each production session constructs its own initial environment.

This fragment deliberately omits String constructors, byte-array representation and proof fields, String operations, Char primitives, and general primitive or axiom admission. In particular, the compiler inventory's 36 required assumptions have not been admitted wholesale. String remains an opaque intrinsic to this checker; its logical constructor representation and associated conversion laws remain future work.

The compatibility evidence compares literal typing and dependent result-type equality witnesses against the explicitly pinned native Lean provider. The witnesses cover empty and embedded-NUL strings, scalar boundaries, combining sequences, and beta/zeta/delta. Separate raw-byte tests compare validation with an independent fatal UTF-8 decoder. Finite comparisons are not a proof of kernel soundness or full Lean compatibility.

A completed compiler/kernel admission must include an explicit account of every remaining primitive and prelude dependency. No reference checker is selected after owned rejection. Public proof authority, publication and joint self-hosting flags remain closed until their own recorded gates pass.
