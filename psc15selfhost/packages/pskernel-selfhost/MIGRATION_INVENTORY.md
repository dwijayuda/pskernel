# PSC1Kernel portable migration inventory

> **Historical document.** This file records the original migration baseline and completed migration strategy. The active architecture and roadmap are `PSKERNEL_SELFHOST_ARCHITECTURE.md` and `DEVELOPMENT_PLAN.md`. Do not use the migration order below to override the current phase plan.

Reference baseline: `packages/pskernel/PSC1Kernel` on
`psc2/psc1kernel-selfhost-portable`, derived from the compiler-only self-host
fixed-point branch at `d4298a712d1e2ea6505185d311e9af10a698b2ca`.

The inventory is generated by
`scripts/psc1kernel-reference-inventory.mjs` using the exact shared source
profile consumed by `check-psc1-source.mjs`.

## Baseline

- semantic modules: **22**
- modules violating the proven portable PSC1 source profile: **22**
- `partial def`: **164**
- namespace occurrences: **36**
- `abbrev`: **10**
- `mutual`: **2**
- private definitions: **14**
- local `let rec`: **67**
- instance declarations: **4**
- one checker-cache subsystem imports/uses `Std.HashMap`

The purpose of this inventory is not to mechanically replace every occurrence.
Each category has a migration policy.

| Category | Migration policy |
| --- | --- |
| namespace | flat explicitly-prefixed declarations in the portable tree |
| abbrev | inline representation/signature or introduce a real PSC1 data type only when semantics require it |
| mutual | rewrite as a dispatcher/state machine or controlled partial worker while preserving Lean ordering |
| partial def | keep during initial executable port when fail-closed; eliminate from trusted admission paths during production hardening |
| private def | deterministic package-prefixed helper name |
| let rec | allowed when it is already in the proven compiler source idiom; review only for resource/stack behavior |
| instances | retain only where the frozen PSC1 profile and generated compiler already support the exact machinery |
| Std.HashMap | replace with owned portable cache/index data; caches remain non-semantic |

## Batch migration order

1. Name and Level.
2. Expr and substitution.
3. Declaration, local context, environment, checker caches.
4. WHNF and inference.
5. Definitional equality.
6. Quotients.
7. Ordinary inductives.
8. Mutual and nested inductives.
9. Complete source closure, canonical `.ps`, generated TS/JS and replay parity.

Every promoted slice must pass:

1. shared PSC1 source-profile audit;
2. Lean 4.34 compilation;
3. PSC1 compilation;
4. canonical Lean-to-ProofScript translation and ProofScript recheck;
5. differential behavior against the frozen reference for the migrated slice.

End-to-end replay and checked-provider integration are later gates, not discovery
mechanisms for ordinary source incompatibilities.
